# P3 实施记录：面试数据层 MySQL 权威化

版本：2026-11-19。范围：`docs/剩余工作量清单.md` §4 P3 明细。

---

## 1. 一句话结论

面试的业务状态（会话、材料、题目、提交）从「Redis 缓存 + 快照反推」整体切到 **MySQL 权威记录**；幂等从「Redis 去重集合 + 分布式 single-flight」切到 **唯一约束 + attemptToken + 版本列**。后端 293 → 255 个 Java 文件，`mvn test` 60 项全绿，真实 DeepSeek 全链路（出题→答题→追问→雷达→报告）闭环通过。

## 2. 新建 6 张表

`admin/src/main/resources/sql/interview_core.sql`（已执行到 `mainshi_agent` 库）：

| # | 表 | 关键列 | 关键约束 |
| --- | --- | --- | --- |
| 1 | `interview_session` | status / flow_status / current_question_no / total_questions / follow_up_count / max_follow_up / version / active_submission_id | `uk_session_id`、`version` 乐观锁 |
| 2 | `interview_material` | parse_status / parse_version / interview_type / resume_score / suggestions_json / resume_context / model_name / prompt_version | `uk_session_id` |
| 3 | `interview_question_item` | question_no / kind(MAIN/FOLLOW_UP) / main_index / follow_up_index / parent_id / points_json | `uk(session_id, question_no)` |
| 4 | `interview_answer_submission` | submission_id / request_id / input_hash / status / attempt_token / attempt_count / score / feedback / response_json / finished | `uk(session_id, question_no)`、`idx(session_id, request_id)` |
| 5 | `ai_conversation` | conversation_id / user_id / status / version | 聊天会话（P4 接普通聊天用） |
| 6 | `ai_message` | turn_id / request_id / seq / role / message_content / model_name / prompt_version | `uk(conversation_id, request_id)` 防重复 |

> 原计划中「回答提交唯一键防重复」「attemptToken 条件更新」都已落地；`ai_message` 正文列从 `content` 改为 `message_content`（`content` 是 MySQL 保留字隐患）。

## 3. 代码侧改动

### 3.1 新增数据层（`dao/store`）

| 类 | 职责 |
| --- | --- |
| `InterviewSessionStore` | 会话条件更新（`commitProgress` 按 `expectedVersion` 乐观锁推进游标）、归属校验 `requireOwned` |
| `InterviewMaterialStore` | 材料 upsert（`uk_session_id` 原地更新，重试出题 `parse_version` 自增） |
| `InterviewQuestionStore` | 主问题/追问同表读写、`replaceMainQuestions`（物理删除旧题，因唯一键）、`appendFollowUp`、`updatePoints` |
| `InterviewSubmissionStore` | `claim`（NEW/RETRY/REPLAY/CONFLICT/ALREADY_ANSWERED/BUSY 六态）、`markSucceeded`（attemptToken 条件完成）、`markFailed`、`averageMainScore`（主问题平均分，无评分返回 null） |
| `InterviewProgressCommit` | 会话游标推进命令对象 |

### 3.2 重写主链路

| 类 | 变化 |
| --- | --- |
| `InterviewFlowStateMachine` | 从「缓存读写状态机」改为**纯计算**：`toFlow/plan/mainIndexOf/followUpIndexOf/isFollowUp`，不再依赖缓存 |
| `InterviewAnswerPipeline` | 会话锁串行化入口 → MySQL `claim` 幂等 → 模型评分（不持事务）→ `commitService` 单事务提交「提交终态 + 追问题 + 会话游标」 |
| `InterviewAnswerCommitService` | 新增：事务内写 `markSucceeded` + `appendFollowUp` + `commitProgress`，版本冲突抛 `VersionConflictException` 整体回滚 |
| `InterviewSessionFacade` | 全部读 MySQL（`materialStore`/`questionStore`/`submissionStore`），去掉「缓存 miss 回源 + 快照反推」分支 |
| `InterviewRecordServiceImpl` | 报告输入全来自 MySQL；`saveInterviewRecordFromRedis` 保留 finalize 锁，去掉缓存依赖 |
| `InterviewQuestionExtractionService` / `InterviewPreparationCommitService` | 出题落库：材料 + 题目 + 重置本轮问答同一事务 |
| `InterviewAiInvoker` | 去掉 single-flight，`call(request, stage, key)` 直接走 guard → `LlmChatClient` |

### 3.3 删除旧层

- `dao/repository`（缓存仓储）、`application/runtime`（快照/重水化）、`application/guard/singleflight`、`service/cache`、`service/InterviewQuestionCacheService|QuestionService|ScoreService`、`application/strategy/AverageInterviewScoreAggregatorStrategy|InterviewScoreAggregatorStrategy`、`config/InterviewAiSingleFlightConfiguration|HotRefreshConfiguration|TurnRepairConfiguration`
- `flow/answer/InterviewAnswerIdempotencyService|InterviewQuestionLockService|InterviewTurnRepairService`
- 实体：`InterviewQuestion`、`InterviewSessionRuntimeColdSnapshot/HotSnapshot/Snapshot/TurnArchive`
- 死代码：`service/model/InterviewRuntimeConfidence|ScoreAggregate|LoadMode`、`api/io/resp/ExpressionRecognitionResponse|Result`（神态残留）
- 幂等/并发语义由 `InterviewSubmissionStore.claim` + `attemptToken` + `version` 承接，无中间态。
