## 1. 目标与边界

按使用者要求，**先把视觉模型的位置全部预留好，密钥留空由使用者自行填写**。本次只做接入与降级，不做真实模型调用验证（无密钥）。

使用者提供的预置信息：

```
VISION_BASE_URL=https://cn-beijing.maas.qianwenapi.com/compatible-mode/v1
VISION_MODEL=qwen3.8-omni-flash
```

这是千问 MaaS 的 OpenAI 兼容多模态端点，`qwen3.8-omni-flash` 为全模态模型，可同时接受文本与图片。

## 2. 配置位（密钥留空）

| 位置 | 变更 |
| --- | --- |
| `admin/src/main/java/.../llm/VisionProperties.java`（新增） | `@ConfigurationProperties(prefix="ai-meeting.vision")`，含 base-url / model / api-key / temperature / max-tokens / timeout / max-image-pages / render-dpi。默认值即上述预置地址与模型；`apiKey` 无默认值。 |
| `application.yaml` | 新增 `ai-meeting.vision` 段，全部走环境变量占位：`VISION_API_KEY` 默认为空，其余已有预置默认。 |

| `docker-compose.yml` | backend.environment 注入三个 `VISION_*` 变量。 |

`isConfigured()` 仅判断 `apiKey` 是否非空。留空时应用照常启动，不构建任何 HTTP 客户端；`LlmProperties`（文本模型 DeepSeek）与 `VisionProperties`（视觉模型）完全隔离，互不影响。

## 3. 代码变更

### 3.1 视觉客户端（新增）

- `llm/VisionChatClient.java`：接口，定义 `isConfigured` / `recognize(prompt, images)` / `describe`。
- `llm/VisionImage.java`：图片载体 record（mimeType + 纯 base64）。
- `llm/OpenAiCompatibleVisionClient.java`：用 `RestClient` 直连 OpenAI 兼容 `/chat/completions`，构造 `image_url`（data URI）+ `text` 的多模态 content；兼容返回 content 为字符串或数组两种形态。**未配置密钥时调用才抛 `ClientException`，不影响启动**。

没有复用 `SpringAiLlmChatClient` 的原因：视觉模型的地址/密钥/模型与文本模型彼此独立，且 Spring AI 的 Media 多模态构造在不同版本间不稳定；直接拼 JSON 对 compatible-mode 端点透明可控。

### 3.2 材料抽取回退（新增 + 改造）

- `llm/document/ResumeMaterialExtractor.java`（新增）：统一入口，三层策略按成本递增：
  1. 文本型 PDF → `PdfTextExtractor` 本地抽取（零成本）；
  2. 扫描型 PDF（无文本层）→ PDFBox `PDFRenderer` 渲染页为 JPEG（DPI/页数可配，默认 150 / 6 页）→ 视觉模型 OCR；
  3. 图片文件（png/jpg/jpeg/webp/bmp）→ 直接送视觉模型。
  视觉未配置时，仅在第 2/3 层抛可操作的 `ClientException`（提示 `VISION_API_KEY`），第 1 层不受影响。
- `interview/flow/extraction/InterviewQuestionExtractionService.java`：注入由 `PdfTextExtractor` 改为 `ResumeMaterialExtractor`；对 `ClientException` 单独捕获并把提示透传前端。
- 对应测试 `InterviewQuestionExtractionServiceTest` 的 mock 同步改为 `ResumeMaterialExtractor`。

### 3.3 前端（图片上传 + 顺带修 bug）

- `NewInterviewView.vue`：`accept` 扩展到 pdf/png/jpg/jpeg/webp/bmp，提示文案同步。
- **顺带修复既有 bug**：原 `before-upload` 钩子在 `:auto-upload="false"` 下不会被 Element Plus 触发，导致 `file.value` 永远为空、选了简历也无法开始面试。改用 `on-change` 钩子取 file，这是图片上传能真正生效的前提。
- `interview.ts` 字段名 `resumePdf` 与后端 `@RequestParam` 一致，图片走同一入口，无需改动。

## 5. 使用者待办（唯一阻塞项）

填入密钥即可启用，**无需改代码**：

1. 本地直连：在 `admin/application-local.yaml` 加：
   ```yaml
   ai-meeting:
     vision:
       api-key: <你的密钥>
   ```
   或设环境变量 `VISION_API_KEY`。
2. Docker 部署：复制 `.env.example` 为 `.env`，填 `VISION_API_KEY=<你的密钥>`。
3. 填好后用一张图片简历或扫描版 PDF 走一次"新建面试"，确认 OCR 文本能进入出题提示词。

未填密钥期间：文本型 PDF 简历面试流程完全正常；图片/扫描件会收到明确提示"需要视觉模型识别，请设置环境变量 VISION_API_KEY"。
