## 2. P1 明细（✅ 2026-11-19 已完成）

完成情况见 `docs/P1-实施记录.md`。以下保留原始拆解，作为该阶段的范围依据；已完成项标注删除线。

### 2.1 先解耦，再删除

顺序不能反：`interview` 包直接依赖 `agent` 包的 4 个类型，先删 agent 会编译失败。

| 依赖类型 | 处数 | 处置 |
| --- | --- | --- |
| `agent.api.io.resp.AgentMessageHistoryRespDTO` | 2 | 新建面试自有 `InterviewMessageHistoryRespDTO`，字段按面试历史实际需要裁剪 |
| `agent.dao.entity.AgentPropertiesDO` | 6 | 面试用到的只有 flowId/模型配置，抽成 `InterviewModelProperties` |
| `agent.application.BusinessAgentResolver` | 5 | 同上，或直接由 P2 的模型适配器取代（**建议合并到 P2 做，避免造一次临时类再删**） |
| `agent.application.BusinessAgentScene` | 5 | 枚举，面试只需要 3 个场景，随上一项一起处理 |

涉及 **9 个文件**：`InterviewSessionController`、`InterviewAnswerPipeline`、`InterviewEvaluationService`、`InterviewFollowUpService`、`InterviewQuestionExtractionService`、`InterviewDemeanorService`、`InterviewSessionFacade`、`InterviewSessionServiceImpl`、`InterviewAiInvoker`。

> 因为其中 5 处是 `BusinessAgentResolver`/`Scene`，而 P2 本来就要用新适配器替换整条模型调用链，**建议 P1 只做 DTO 解耦（2 处 + 历史接口），resolver 相关留给 P2 一次性替换**，可以少写一版过渡代码。

### 2.2 删除媒体/语音

| 对象 | 规模 |
| --- | --- |
| `media` 包 | 9 个类（2 个 Controller：`WebSocketController`、`XunfeiTtsController`，共 8 个端点） |
| 相关测试 | `XunfeiAudioServiceAssemblerTest`（含 R12 的 `@Disabled` 用例）、`AudioTranscriptionWebSocketHandlerTest`、`streamingMedia/` 包下 2 个测试类 |
| 讯飞配置 | `XunfeiLatProperties`、`XunfeiSecretStartupValidator` |
| 配置项 | `application.yaml` 的 `xunfei.lat-key.*`、`require-xunfei-secrets` |

**卡点（必须一起改，否则删完起不来）**：`XunfeiSecretStartupValidator` 在启动时校验讯飞密钥。删除媒体后它若还在，缺密钥直接启动失败。要么删掉该 Validator，要么把校验范围缩到"只有用到语音时才校验"。

### 2.3 删除神态

比"删一个 service"大得多：**5 个专属类，但有 30 个文件引用 `demeanor`**，集中在雷达图/评分/运行时快照/报告四条链上。

| 需改的点 | 说明 |
| --- | --- |
| `WeightedRadarComputationStrategy` | 去掉 20% 神态轴，保留项归一化为 31.25%/68.75%；另需处置第二套 `PROFESSIONAL_SKILLS_*`(0.70/0.30) 分支 |
| `InterviewRecordServiceImpl` / `InterviewScoreServiceImpl` | 移除神态分数写入 |
| `InterviewSessionRuntimeSnapshot(Service)` / `ColdPatch` / `HotRefreshRequest` | 快照结构去神态字段，旧快照需能反序列化（保留字段但不再读取更安全） |
| `RadarChartDTO` / `DemeanorScoreDTO` / `DemeanorEvaluationReqDTO` | DTO 清理 |
| `InterviewErrorCodeEnum` | 去掉神态相关错误码 |

### 2.4 讯飞整体退出

`25 个 Java 文件` 引用 `xunfei`，其中 `toolkit/xunfei` 下 6 个类（`XingChenAIClient`、`SparkIatService`、`SparkIatUtil`、`AgentPropertiesLoader`、`AIContentAccumulator`、`RoleContent`）。**pom 里没有讯飞 SDK 依赖**，全是手写 HTTP/WS，所以不需要处理依赖冲突，只是删代码。

### 2.5 前端停用入口（不重写，只止损）

React 侧 10 个文件引用语音/摄像头/agent：`CameraPreview.tsx`、`useMicrophonePcmStream.ts`、`useMicrophoneRecording.ts`、`agentService.ts`、`xunfeiTtsService.ts` 等。P1 只需把这些入口摘掉或置灰，避免它们持续请求已删除的接口。

## 7. 建议顺序与理由

```
P1(解耦+删媒体/神态)  →  P2(模型直连)  →  P3(MySQL)  →  P4(退役 Mongo)  →  P6(验收)
                    ↘   P5(Vue，可与 P1~P4 并行)   ↗
```

- **P1 先做 DTO 解耦、后删代码**：删一半再改会让编译长期是红的。
- **P2 之前不要动存储**：模型链路不稳，改了存储也验证不了。
- **P5 提前并行**：前端不依赖后端实现，只依赖契约；等 P4 完再开始会把工期叠加。
