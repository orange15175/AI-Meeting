# P2 实施记录：模型直连

日期：2026-11-19。对应计划 `docs/文字面试平台重构实施计划.md` §11 P2。
结论：**P2 已完成**，并已用真实 DeepSeek 密钥跑通「出题 → 评分 → 追问 → 雷达图 → 报告落库」全链路。

## 1. 改造前后

| 维度 | 改造前 | 改造后 |
| --- | --- | --- |
| 模型入口 | `XingChenAIClient` 调星辰 Agent 工作流（`flow_id` + `api_key` + `api_secret`） | `LlmChatClient` 直连 DeepSeek / OpenAI 兼容端点 |
| 提示词 | 主体在星辰工作流里，Java 侧只有一句英文指令 | `classpath:prompts/**/*.v1.md` 版本化文件，`PromptLibrary` 加载渲染 |
| 简历文件 | 上传到星辰对象存储，模型侧解析 | 本地磁盘存储 + PDFBox 本地抽取文本 |
| 凭据来源 | `agent_properties` 表逐行存放 | 统一配置 `ai-meeting.llm.*`（环境变量或 `application-local.yaml`） |
| 输出契约 | 容忍 `sugest` 错拼、`smallTalk` 回退、`choices[].delta` 包装 | 严格 JSON，字段固定；解析失败即失败，不再猜字段 |

## 4. 关键代码改动

- `InterviewAiInvoker`：只换最内层。签名由 `(prompt, sessionId, AgentPropertiesDO, stage, key)` 收敛为 `(LlmRequest, stage, singleFlightKey)`；限流/熔断/single-flight 外壳原样保留。
- `InterviewEvaluationService`：单次调用替代「工作流 + prompt 兜底」两次调用；`normalize` 只认契约字段，缺字段补默认值而不是塞 0 分。
- `InterviewFollowUpService`：追问改由模型判定 `end_interview`，模型不可用时仍回退到评分器给出的追问建议。
- `InterviewQuestionExtractionService`：先落盘、再抽文本、再调模型；`resumeFileUrl` 由「星辰返回的 URL」改为「相对 storage.base-dir 的路径」。
- `InterviewAnswerPipeline` / `InterviewSessionServiceImpl`：去掉 Agent 解析；新会话 `interviewerAgentId` 置 `null`（报告里该字段随之为空，语义正确）。
- `AgentMessageServiceImpl` / `AgentFileAssetServiceImpl` / `AgentController`：通用聊天改直连（系统提示词取 `chat-general.v1.md`，历史按 `LlmMessage` 传递），附件改本地存储，`agentId` 统一用内置标识 `0`。
- `InterviewQuestionServiceImpl`：删掉 `sugest` 兼容分支与 `resumeScore/score` 混用之外的别名读取。
- R3（评分要点提前下发）：`suggestions` 重新定义为**候选人可见的简历/表达改进建议**，提示词里明确禁止输出评分要点与考察意图，因此出题响应继续返回该字段也不再泄露评分口径（前端 `resumeSuggestions` 语义不变，不必改契约）。

## 5. 配置

`application.yaml`：

```yaml
ai-meeting:
  llm:
    provider: ${LLM_PROVIDER:deepseek}
    base-url: ${LLM_BASE_URL:https://api.deepseek.com}
    api-key: ${LLM_API_KEY:}
    model: ${LLM_MODEL:deepseek-chat}
    temperature: 0.3
    max-tokens: 4096
    timeout-seconds: 120
    scenes:
      interview-question-extraction: { temperature: 0.2, max-tokens: 6000, timeout-seconds: 180 }
      interview-answer-evaluation:   { temperature: 0.1, max-tokens: 1024 }
      interview-follow-up:           { temperature: 0.5, max-tokens: 512 }
  interview:
    extraction:
      question-count: ${INTERVIEW_QUESTION_COUNT:10}
```

切换 Qwen 只改三行：`provider: qwen`、`base-url: https://dashscope.aliyuncs.com/compatible-mode/v1`、`model: qwen-plus`。

真实密钥写在 `admin/application-local.yaml`（`.gitignore` 已覆盖，启动日志只打印 `apiKeyPresent=true`）；`.env.example` 同步为 `LLM_*` 四项。

## 7. 遗留与风险

| 项 | 说明 | 归属 |
| --- | --- | --- |
| 扫描版 PDF | 无文本层 → 出题直接报 `resume pdf contains no extractable text`，不做 OCR | P5/P6 视产品需要决定是否接 OCR |
| `resumeFileUrl` 无下载端点 | 现在存的是相对路径，前端未使用该字段；需要展示原件时再补 `/resume/{sessionId}` 下载 | P3/P5 |
| `ai_properties` 仍是普通聊天的模型来源 | 通用聊天选哪家模型由该表决定，与面试链路的统一配置并存 | P4/P6 统一 |
| `agent_properties` 仅剩后台 CRUD 读写 | 业务链路（面试/通用聊天/附件）已全部不读 | P6 清理 |
| Single-flight 仍在用 | 计划要求 P3 用 MySQL 唯一约束替代后再删 | P3 |
| 缺少「模型返回非法 JSON」的 HTTP 级用例 | 现由单测与解析器兜底覆盖，未做故障注入 | P6 验收矩阵「模型」行 |
